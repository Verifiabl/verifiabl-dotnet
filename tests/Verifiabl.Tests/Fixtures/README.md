# Cross-SDK fixtures

These files are generated by the Node SDK ([verifiabl-node](https://github.com/Verifiabl/verifiabl-node)), not by hand or by this repo:

- PNG parity fixtures (`node-png-*.rgba.deflate`, `node-png-meta.json`) come from `scripts/generate-dotnet-png-fixtures.mjs`.
- SVG parity fixtures (`node-svg-*.svg`, `node-svg-meta.json`) come from `scripts/generate-dotnet-svg-fixtures.mjs`.
- The embedded frame assets the rasters are compared against (`src/Verifiabl/Assets/*.vfr1`) come from `scripts/bake-frames.mjs`.

All of them must be regenerated together, from the same Node commit, whenever the Node compositor, the badge frame, or **the encoded scan URL** changes — otherwise `NodeSdkParityTests` is asserting parity against a stale raster. The Node repo's frame-asset freshness test catches a frame change that was not re-baked at the source.

Regenerated 2026-08-12 from verifiabl-node `1659bbd` for the VER-369 fragment scan URL. Anything that changes the QR's encoded content changes every one of these, not just the frame.
